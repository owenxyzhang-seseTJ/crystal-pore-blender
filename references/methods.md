# 孔隙定义、周期性与验收

## Contact Surface 的计算

令框架原子中心为 `r_i`，vdW 半径为 `R_i`。在周期晶格中，净空是 `c(x) = min_i,t |x - r_i - t @ A| - R_i`。半径 `p` 的探针中心可达集合满足 `c(x) >= p`。

本流程先在中心集合中保留周期贯通的分量，再构造完整球形探针可占据的空间。Contact 标量场为 `p - distance(x, connected_center_set)`，其零等值面由 marching cubes 提取。对 `c(x) = p` 直接作等值面，只得到探针中心区域边界，与这里的 Contact Surface 不同。

本脚本为效率将远离所需判定阈值的净空数值截断。因此 `accessible_centers` 和 Contact 表面可用于绘图；不能从截断净空求最大腔径。Di、Df 采用同一半径模型实际运行成功的 Zeo++ 输出，或另做明确支持这些量的计算。

矩形网格表示的是周期标量场，不是有限框架外的“无限空白”。计算先在完整周期晶胞中完成，裁剪只用于展示。倾斜晶格的相邻镜像数量依据倒易基底得到的晶胞面间距和所需探针/原子半径确定，不能一概假设正交立方晶胞。

## 周期连通性

周期边界局部标签相接并不自动证明贯通。`periodic_connectivity.py` 记录接合中的整数位移，闭环产生非零 winding 才确认周期贯通。轴向依 winding 的张成空间或原生孔网结果确定；`[100]` 等是直接晶格方向，不能把它与晶面法向混淆。

一条孔道的多个周期镜像，在有限裁剪框中可能呈现两条或更多平行管。先用指定客体/孔道锚点确定一个有限连通分量，再检查其 mesh 连通性。单条无限孔道可以沿晶轴起伏和蜿蜒，不能为了美观拉直。

## 半径与独立库

本次采用的 Zeo++ LSMO 默认表（Å）：H 1.09、C 1.70、N 1.55、O 1.52、S 1.80、Fe 2.00、Co 2.00、Zn 1.39。此处只内置已用到的元素；未知元素显式提供有来源的半径，不猜测。

原生调用示例：

```sh
network -ha -res zeopp.res -chan 0.9 zeopp.chan framework_for_pores.cif
```

`-ha` 会提高几何分解精度，原生输出中出现的粒子数可能是高精度算法内部球分解数，不能当成源 CIF 原子数。`-v1` 输出的是 Voronoi 数据，不是输入半径表。

默认脚本只在所用半径与内置、已核查的 Zeo++ 默认表一致时调用原生默认模型。有自定义半径时，先配置一致的原生半径输入，核对该版本的参数格式；不要把不同半径模型的结果写成同一验证。

此路线是“Zeo++ 孔网验证 + 周期场 Contact Surface 构网”，不是 Zeo++ 原生表面网格或 Mercury 原生导出。用户明确要求 Mercury 原生网格时，先定位可用导出或合法 API；若不可用，说明具体限制并在用户接受替代路线后再继续。

工具实际情况随环境变化，应核查当前运行结果。CrystalCanvas 可用于体场显示，pyMolDyn 有 cavity 计算，iRASPA 有孔隙相关显示；链接/安装存在不等于已经成功处理当前 CIF。

## 轻微平滑与半剖

Taubin 正负步平滑三轮，开放端口边缘固定。它仅作用于显示顶点，原始 mesh 另存。测量各顶点位移；限值按当前网格分辨率与结构决定。本次最大值约 0.03 Å，不代表所有新材料都达到这个数值。

纵向半剖的平面法向应垂直实际孔轴；本渲染器先将侧视相机方向投影到该法平面，并让孔轴横向展开。半剖面通过所选客体锚点平均位置。对网格逐三角形求交，保留背面半壳，开放切面；不能用删除面中心点代替精确求交，也不加遮挡客体的平面盖板。

切开后仍保留框架、客体完整坐标；改变客体的球径属于显示参数。若用户要的是横向切片/端视横截面，而非本次纵向半剖，需要另选垂直孔轴的切面和相机，不能用这里的 longitudinal 模式冒充。

## 必要验证

- 晶格与源组成一致，去客体的元素和原子数正确。
- 半径、探针、表面定义、网格精度和贯通判定有记录；首次计算按需要检查粗细网格体积分数差异。
- 单孔分量及所有指定锚点一致；侧壁不被裁剪框截断。
- 框架及客体各原子的分数坐标只允许整数平移；显示配体完整，没有因单原子 wrap 拉断键。
- 保存后重开 `.blend`，检查实际坐标、mesh 顶点、客体数量与默认图层。
- 查看最终文件的实际渲染图，而非只看 scene JSON 或命令退出码。确认水/客体易辨认、孔壁颜色不过暗、透明 PNG 真正含透明通道、白底版本与同一透明图对应。
- 只运行与新改动相关的检查，不用形式化的重复启动或不相关测试替代真实输出检查。
